## 二、已修复的 bug（3 类 4 处）

### 🐞 1. 标签路径只支持官方布局，且失败时静默产出空目标（最重）
`FireDataset` 用「图片路径上一级的上一级 + /labels/」推导标签，只匹配官方布局
`<root>/<split>/images/x.jpg`。我们的 ultralytics 布局 `<root>/images/<split>/x.jpg`
差一层，推导出的路径不存在 → **静默当负样本**，训练不报错但学不到任何框、评估
mAP=nan 无提示（本次冒烟首跑即此现象）。
**修复**：`datasets/fire_dataset.py` 改为把路径中最后一段 `images` 组件换成 `labels`
（两种布局通吃），无 `images` 组件时回退原推导。

### 🐞 2. mAP 评估把 10 个 IoU 阈值的预测混进同一条 PR 曲线
`train.py evaluate()` / `eval.py run_eval()` 按「每图 × 每阈值」平铺拼接 tp/conf/cls，
`ap_per_class` 对混合数组只算一条曲线再赋给每个阈值 → **mAP50:95 ≡ mAP50，且 mAP50
本身被掺入假阳性偏置**（`ap_per_class` 的 docstring 本来就写明应传 `(n_preds, n_thrs)`，
调用端没按契约实现）。
**修复**：`metrics.ap_per_class` 支持 2-D tp（按阈值分列 cumsum）；两个调用端改为
`np.stack([...], axis=1)` 每检测一行、GT 类别只计一次。构造用例阳性对照：A(IoU 0.6,
conf 0.9) + B(IoU 0.9, conf 0.5) + 1 GT → AP50=1.000、AP50:95=0.653（= (3×1+7×0.5)/10，
手算吻合）。

### 🐞 3. eval.py 在 GPU 上必崩
`torch.synchronize()` 不存在（两处，line 35/42），应为 `torch.cuda.synchronize()`——
CPU 上因短路永不出错，**说明 eval 入口此前没在 GPU 上运行过**。已修复。

## 四、复现命令（已验证）

```bash
cd pwm
python datasets/check_dataset.py -h          # 数据校验/划分（官方布局用）
python train.py --subset 96 --epochs 2 --batch-size 8 --name smoke_test   # 冒烟（已跑通）
python train.py --epochs 300 --batch-size 16 --name pwmnet                # 全量
python eval.py --weights runs/smoke_test/weights/best.pth --split val --conf 0.25
python inference.py --source ../e2e/_real_images/fire1.jpg --weights runs/smoke_test/weights/best.pth
```

## 五、其他提示

- `--subset / --val-subset` 按列表顺序截取，splits 已洗牌（seed 42）避免截出全负样本子集
  （本次冒烟曾因此 mAP=nan——全负子集无 GT 时 nan 属正确行为，但易误判为 bug）。
- 这份是从零训练（无 COCO 预训练起点）+ 简化头（无 DFL/TAL），同数据轮数下精度预期低于
  `scripts/yolo/pwm` 的 ultralytics 路线（COCO 迁移起点）；两条路线定位不同：本份=论文忠实
  复现，ultralytics 版=性能优先。对比时注意评测口径（ultralytics 用其自带 mAP，本份用
  本目录 COCO 风格实现）。
- 上平台（FIRE_YOLO_ENDPOINT §2 协议）需一个小适配器把 inference 输出转
  `{detections:[...], source, model}` JSON；平台侧零改动。
- 冒烟产物 `runs/smoke_test/`（2 epochs toy 权重，仅证明管线，勿用于演示/对比）。
