# 演示脚本(2026-09 全功能版)

> 对应追踪清单 E-3(演示材料)。按钮与页签名称均与当前 UI 逐一核对。
> 标注 ⏱ 的为建议用时;全流程约 12 分钟,8 分钟场合按 §八 裁剪。
> 开播前先跑 `python e2e/demo_readiness.py`(§〇),全绿再开录。

## 〇 开播前检查(⏱5 分钟,不上镜)

1. 启动后端:`cd backend && python -m uvicorn app.main:app --port 8000`(首次启动环境预热约 1 分钟)。
2. 启动前端:`cd frontend && npm run dev`,打开 `http://localhost:5173`。
3. 运行 `python e2e/demo_readiness.py`:后端/前端/GLM 在线/VLM 已配置/Key 变量逐项 ✅。
4. 干净存档:删除 `data/analysis_store.db` 后重启后端(清空历史测试任务),历史页应为空。
5. 看首页模型徽标:GLM 在线时显示「LLM 在线」(离线显示「LLM 离线」,模型名见 VLM/LLM 配置,不在徽标展示);VLM 显示"已配置"。若 GLM 离线先看 §九。
6. 免费档模型随时可能限流(与时段无关),演示中若见"离线规则"徽标属预期降级,照常讲(§九)。

## 一 幕 0 · 开机与林区态势(⏱1 分钟)

1. 打开首页,指出"系统运行正常"。
2. 切到「林区态势」:紫金山真实等高线(N32E118.hgt 来源标注)、火点、机群标记、水源与道路图层、比例尺。
3. 提一句环境数据来源徽标(真实 GIS/气象;断网时标注 offline/demo-fallback,不虚构)。

## 二 幕 1 · 影像/视频接入 + VLM 视觉解释(⏱1.5 分钟)

1. 在「现场影像接入」拖入一张航拍 JPG(可多选图片组成序列;也可直接拖 MP4,系统自动均匀抽帧)。
2. 勾选「上传时调用 VLM 解释」,点「启动智能研判」。
3. 研判完成后在调度建议面板展示 **VLM 视觉解释块**:来源徽标 `vlm-glm-4.6v-flash · 提示词 v4`(真实视觉模型在线产出)、两三句视觉摘要、事实行(图像质量/人员/烟雾/视觉规模/时序)、需人工复核旗标。
4. 口径:VLM 只描述看得见的事实;FLP、面积、调度等数字全部出自规则引擎(VLM 被禁止输出这些,平台另有契约守卫兜底)。
5. 模型状态徽标:YOLO"待接入"= 检测接收面已就绪、等真实 PWM-YOLO 服务(接口已用 mock 全链验证,到位即插即用)。

## 三 幕 2 · 研判与审批门(⏱2 分钟)

1. 方案摘要:FLP 负荷、主/备方案数、任务分工 chips、时间区间、硬约束、缺口(如 water_20l)、重规划触发器;行尾"数字来源条"(FLP ← 火情负荷评估 · 时间区间 ← 离散轮次仿真 · 约束/缺口 ← 规则引擎硬约束校验)。
2. 两个口径:可控火 →"建议立即启动一级处置响应"+处置时间窗;极大火(large-fire)→"建议立即请求增援"+时间窗为"—",强调**不产虚假时间窗**。
3. 审批门:任务状态"待确认",可输入原因后点「批准主方案」;可补展示「驳回」——任务回到待确认、资源锁释放,原因必填留痕。AI 只建议,人来批准。

## 四 幕 3 · 多 Agent 协作(⏱1.5 分钟)

1. 切「Agent 协作」页签(或大屏右栏协作流,默认第一屏可见):指挥员建案 TASK_ASSIGN、侦察 FINDING、压制 PLAN_PROPOSAL、审批 APPROVAL_REQ 等黑板消息逐条出现,含 frm→to 与来源标注(GLM/规则)。
2. 头部 GLM 徽标:在线时六角色研判由 GLM 参与且带确定性降级兜底。

## 五 幕 4 · 推演与演练(⏱2.5 分钟)

1. 批准后地图上无人机起飞(四旋翼标记 + SOC 电量环 + 作业脉冲),自动推演每 6 秒一轮。
2. 指挥中枢演化曲线:FLP 随轮次变化,重规划打点。
3. 演练注入(演训事实行可见):⚔ 单机失能 → 故障消息 + 后备机自动补位(方案内换机,不过审批门);🌪 风变跨档 → 触发重规划,新方案 v2 **再次经过审批门**。
4. 关键口径:重规划续接当前火势/风速/SOC,机群不重飞、目标不漂移。

## 六 幕 5 · 结案回收(⏱1 分钟)

1. 火势扑灭(FLP 压平)后任务进入收尾:全部作业机返航回收(计入 SOC 消耗),协作流出现 RECOVERY 消息与事件。
2. 任务状态转"已完成",资源锁释放。强调闭环:从报警到结案全自动推进,但每次开火与重规划都过了审批门。

## 七 幕 6 · 报告与指挥员问答(⏱1.5 分钟)

1. 「在线查看报告」:结论卡 + 统计格 + 全链路时间线 + 原始 JSON;「下载报告」得归档 JSON。
2. 指挥中枢问答面板:问"水剂还剩多少?""为什么出动这些无人机?"——GLM 回答全部接地任务实时数据(库存/方案),数字审计对编造数字标 ⚠。

## 八 幕 7 · 三维与广播(⏱1 分钟,8 分钟版可删)

1. 地图工具栏切「三维」:真实 DEM 地形三维呈现,火点/机群同场景。
2. 打开「疏散广播」开关:有人分支疏散路线生成时语音口播(Edge TTS,失败自动回落浏览器语音)。

## 九 降级预案(演示中如实讲解)

| 状况 | 表现 | 讲法 |
|---|---|---|
| GLM 文本模型限流 | 头部徽标变"离线规则",研判/问答走确定性降级 | "规则引擎是底线,演示永不中断" |
| VLM 限流 | 解释块回落规则解释(徽标注明 rule-explainer-fallback) | "视觉解释降级,数字链路不受影响" |
| 断网 | 环境来源标注 offline/demo-fallback | "数据来源诚实标注" |

## 十 口径红线

- 视觉模型 **glm-4.6v-flash 已真实接入**(免费标准 API);不要说"未来接入 VLM"。
- YOLO:当前为 fixture(界面已标注),真实 PWM-YOLO 对接已备好,到位即插即用;**不得宣称已真实识别**。
- 所有调度数字出自冻结规则公式;LLM/VLM 只做建议、描述与叙述,全部带来源标注;开火与重规划必过人工审批。
