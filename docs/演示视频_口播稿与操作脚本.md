# 演示视频 · 口播稿与操作脚本

> 成片目标 **6 分 30 秒**（素材多录，等待段加速）。结构：屏幕录制 + 单独口播 → 剪辑对齐 + BGM。
> 时间码均为**成片时间码**。口播按句编号——录废了只重说那一句，剪辑时切掉废句即可。

## 一、录制前检查单（开录前 10 分钟过一遍）

- [ ] **三个服务在线**：
  ```bash
  # 终端1：YOLO 检测服务
  python yolo_server/server.py --port 9000
  # 终端2：后端
  cd backend && set FIRE_YOLO_ENDPOINT=http://127.0.0.1:9000/detect && python -m uvicorn app.main:app --port 8000
  # 终端3：前端
  cd frontend && npx vite --port 5173
  ```
- [ ] **YOLO 预热**：服务刚启动后先随便传一张图研判一次（或 `curl -X POST --data-binary @e2e/real/AoF07718.jpg http://127.0.0.1:9000/detect`），否则首帧推理超时会失败一次
- [ ] 浏览器 **1920×1080 全屏**、隐藏书签栏、只留一个标签页、系统勿扰（关闭微信弹窗）
- [ ] 录屏软件（OBS）30 帧、麦克风开、先试录 10 秒听底噪
- [ ] 主素材图：`e2e/real/AoF07718.jpg`（已验证 5 个检测框）；备用 `AoF07719.jpg`（III 级大火，增援剧情）
- [ ] 数据库里有历史任务即可（任务管理/数据分析页的表格镜头用）；没有就先按镜头 2-4 跑一遍
- [ ] VLM 免费档限流：开录前如果 30 分钟内没调过 VLM，一次就能成；若界面出现「规则映射」回落标注，等 2 分钟重录该镜头

## 四、剪辑与后期

1. **对齐**：以每段口播第一句的起始时间为锚，把对应屏幕素材段铺到该时间码下。
2. **变速**：研判过程条（镜头 2 的 40s）、推演等待（镜头 4 的 30s）分别 4×/3× 加速，其余原速。
3. **剪切**：口播废句整句剪掉（重录句拼在原位）；屏幕废操作整段剪掉；句与句之间留 0.3s 气口。
4. **BGM**：低沉科技感氛围乐，音量 -18dB（口播 -6dB），镜头 8 结尾渐弱。
5. **字幕**：口播全自动识别字幕即可，术语校正表：FLP、YOLO、GLM-4.6V、SOC、VLM。
6. **角标**：镜头 2 右下角可加小字「真实火场照片 · PWM-YOLO 真实检测」；镜头 4 加「5 分钟/轮 · 离散推演」。

## 五、应急预案

| 状况 | 处理 |
|---|---|
| 研判失败一次 | YOLO 冷启动超时——立刻重传同一张图再研判（第二次必成），失败段剪掉 |
| 徽章显示「回退·规则映射」 | VLM 被限流——等 2 分钟重录镜头 2；或先录其他镜头 |
| 提示「资源被其他任务锁定」 | 任务管理里把「执行中/待确认」的旧任务终止即可 |
| 数据被清空 | 镜头 2-4 现场重跑一遍即重新生成全部数据 |
| 服务被关 | 按检查单三条命令重启 + YOLO 预热 |

## 六、两条录制纪律

1. **口播里的数值以屏幕为准**：稿中「22-27 分钟」「-14.52」「99.3%」等数字来自预演，实际录制时每次推演结果可能略有差异——**开录每个镜头前先瞄一眼屏幕，把稿子上那个数口头替换成屏幕上的数**再录那一句，避免音画对不上。
2. **备用剧情（可选加分镜头）**：如果想展示「失控→请求增援」，用 `e2e/real/AoF07719.jpg`（III 级高风险大火）走一遍研判——调度结论会出现「失控可能·请求增援 → 增援已出动·火力扩大」的完整剧情，口播可加一句："当火情超出处置能力时，平台会自动请求增援，扩大战力。"插在镜头 3 末尾或镜头 4 都可。
