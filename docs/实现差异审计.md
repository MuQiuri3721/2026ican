# 文档与代码实现差异审计（2026-09-03）

> **✅ 复核结论（2026-09-07）**：本审计的 P0/P1 缺口已全部兑现（状态事务、规则单源、报告归档、测试补齐、前端旧口径清理，明细见修改追踪清单 QA-1/QA-2 与 09-04~07 各批次）；P2 外部能力中 **VLM 已真实接入上线**（glm-4.6v-flash，E-2 完成）、**视频抽帧已接入管线**、SQLite/SSE 均已落地；仍开放项=YOLO 权重（E-1，接收面就绪）、真实飞控/GIS 导航（仿真边界，属方案范围）。本文保留作为 09-03 时点的差距快照。

## 结论

当前项目已经可以完成一条可运行的演示闭环，但不能宣称项目方案中的所有能力都已实现。应将能力分为三类：

1. **已实现并已接入运行链**：FastAPI/Vue 基础工作台、紫金山环境查询、DEM 等高线、2+4+2 资源 fixture、部分 V1 规则、任务审批/轮次/报告 API。
2. **有代码但未完整兑现规则**：FLP 网格、SOC/充换电、人员分支、重规划、状态机、库存事务、Skill 链和报告归档。
3. **依赖外部资源、当前未实现**：真实 YOLO 权重、真实 VLM、真实视频流、真实 UAV GPS/飞控、生产 GIS/A*、SQLite/SSE。

因此“测试通过”目前只代表现有合同测试和前端构建通过，不代表方案文档的全部验收场景已经通过。

## 一、项目方案要求与当前状态

```text

→ 环境数据
→ 无人机/库存状态
→ 智能体综合分析
→ 规则引擎调度
→ 灭火/补给/返航
→ 新监测结果
→ 再决策
```

当前状态：

- 图片上传：已实现；
- 视频文件接收：已实现，但不等于视频抽帧分析；
- YOLO真实推理：未实现，默认 fixture/适配器；

- 反馈重规划：API存在，逻辑部分实现；
- 归档：JSON报告已具备，但任务索引仍是内存。

### 2. 无人机分工

```text
E1–E4：灭火处置
```

代码的数据池已升级为 8 架，但仍需检查所有前端 fallback、旧 Tool 和旧文案，不能让任何运行路径继续使用 DR-01/DR-02/DR-03 或三机模型。

## 二、规则文档与代码差异

### 1. FLP 网格

文档要求：

```text
B_i = 10 × I_i × K_fuel × K_wind × K_slope
B_total = ΣB_i
```

当前已经有 `build_fire_grid` 和 `calculate_flp_load`，但必须确认所有主分析入口都使用网格结果，而不是重新用：

```text
fire_area_m2 / 常数
```

面积可以用于界面展示，但不应替代 FLP 调度依据。

### 2. W20/C6

文档要求：

- 植被火使用 W20；
- 电气热点使用 C6；
- 同一架次不能混装；
- W20 20L、模块总质量22kg、4L/min；
- C6 6kg、模块总质量14kg、1.5kg/min；
- CO₂不用于开放森林地表火常规处置。

当前已有模块字段和兼容函数，但需继续验证：

- C6 仿真是否错误使用植被 κ；
- 模块库存是否在审批时占用、作业时扣减、返航时退回未使用量；
- 监测是否重复扣除模块；
- `agent_remaining` 单位是否始终与模块一致。

### 3. SOC

文档要求：

```text
SOC_need = SOC_outbound + SOC_task + SOC_return + SOC_reserve
```

当前已有 SOC 计算、返航25%和分钟推进，但仍需核验：

- 去程/返程距离是否使用正确单位；
- GPS 经纬度和 x/y 是否混算；
- W20/C6 总质量是否进入耗电；
- SOC低于35%是否禁止远程任务；
- SOC低于15%是否进入应急回收；
- 换电是否扣 `battery_packs`；
- 充电是否按100%/h或60%/h执行；
- 任务状态是否随 SOC 合法转换。

### 4. 水源选择

文档要求同时满足：

- available；
- safe_access；
- capacity_remaining≥20L；
- 路线不穿越高风险网格；
- 取水后返航 SOC≥25%；
- 比基地补给至少节省5分钟。

需要重点核验 `select_water_source` 的时间收益公式、demo 水源字段兼容和调度主链是否真正调用该 Tool。仅有 Tool 存在不等于方案实际使用它。

### 5. 方案评分

文档要求：

```text
J = 0.40T_norm + 0.30B_residual + 0.15E_norm + 0.10M_norm + 0.05N_change
```

需要确认：

- 主方案是否真的用 J 最小值选择；
- 备选方案是否按 J 排序；
- 不可行方案是否不参与主方案；
- 评分中的时间、耗电、物资、换机次数是否来自实际仿真；
- 前端是否展示评分分解。

### 6. 充电/换电/补给

文档要求：

```text
基地充电：100% SOC/h
前向补给点：60% SOC/h
换电：5min，SOC=95%
W20基地补水：4min
W20就地补水：8min
C6模块更换：5min
SUP10交付：2min
```

当前已有部分 Tool 和仿真代码，但需要补充验收：

- 换电库存必须减少；
- 旧电池进入 charging；
- 补给点库存变化；
- W20/C6模块不重复扣减；
- 任务中断时事务回滚；
- 无电池/无模块时输出资源缺口。

## 三、Skill 与实际主链差异

文档建议链路：

```text
fire_perception
→ environment_assessment
→ fire_assessment
→ people_assessment
→ candidate_generation
→ constraint_filtering
→ dispatch_scoring
→ route_planning
→ approval_preparation
→ task_execution
→ closed_loop_monitoring
→ report_archiving
```

当前已经注册新 Skill，但必须确认：

1. `CandidateGenerationSkill` 是否唯一调用 `deterministic_v1_dispatch`；
2. `ConstraintFilteringSkill` 是否消费真实计划，而不是旧 assignment；
3. `DispatchScoringSkill` 是否消费真实 J 分数，而不是简单按任务数量计算；
4. `ApprovalPreparationSkill` 是否输出真实方案摘要；
5. `TaskExecutionSkill` 是否等待用户批准；
6. `ClosedLoopSkill` 是否消费当前 Store 快照；
7. `ReportArchivingSkill` 是否对应真实 JSON 报告；
8. `FireAnalysisSkill` 旧入口是否绕过新链；
9. `AnalysisService` 是否仍额外调用旧 `run_demo_analysis` 造成双算。

如果旧 Skill 仍可通过 `/api/skills/{skill_name}/run` 单独执行，需要明确它是兼容接口，不能与主任务结果混用。

## 四、任务状态和审批差异

文档要求：

```text
queued
→ running
→ awaiting_confirmation
→ approved
→ executing
→ replanning
→ awaiting_confirmation
→ executing
→ completed
```

需要重点确认以下未完成点：

- approve 后是否从 approved 进入 executing；
- 未批准任务是否完全禁止 `/api/monitor` 和 `/api/tasks/{id}/rounds`；
- adjust 是否直接生成新 plan version；
- replan 是否释放旧资源锁；
- 新方案是否重新审批；
- 终止、拒绝和失败是否都释放锁；
- 方案版本是否有并发保护；
- 每个状态变更是否有 before/after 事件；
- 所有写操作是否支持幂等键。

当前 `AnalysisStore` 已有部分锁和幂等能力，但仍需针对这些场景补测试，不能仅依据普通 happy path 测试。

## 五、反馈闭环差异

文档要求每5分钟输出：

```json
{
  "round": 2,
  "before": {},
  "after": {},
  "changes": [],
  "replan_required": true,
  "replan_triggers": [],
  "next_action": "reinforce"
}
```

需补齐：

- before 必须是真实上一轮快照，而不是请求里传来的新值；
- after 必须包含真实 fleet/inventory/SOC/药剂/状态；
- changes 必须列出差异；
- next_action 必须明确；
- 风档触发必须基于档位；
- FLP+20%触发；
- SOC<25%触发；
- 药剂、通信、健康度、人员和路线变化触发；
- 触发后自动生成新方案版本或明确要求用户确认重规划。

```text
model
mode
source
fallback_reason
```

## 十二、最终判断

当前项目不是“所有方案已经实现”，而是：

```text
基础平台：可运行
规则框架：大部分已编码
主链串联：需要继续收敛
```
