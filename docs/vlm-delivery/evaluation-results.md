# VLM 测试统计报告（evaluation-results）

- **测试对象**: glm-4.6v-flash（智谱标准API，免费档）
- **测试日期**: 2026-09-06（第1天：前6组案例+提示词v1/v2；第2天：12组全量+提示词v3/v4定稿）
- **交付提示词**: **v4**（全文见 [prompt-v4.md](prompt-v4.md)；版本沿革见 §2）
- **判卷方式**: 自动四层判卷（JSON解析 → 结构/枚举/身份回显 → 红线禁止项扫描 → 人工预期检查），证据逐次落盘、不人工改写

## 0. 一句话结论

**内容能力达标（内容检查通过率 90.6%，红线禁止项 48 次调用 0 违规），格式纪律需服务端校验兜底（残留围栏/枚举错误约 15–20%，可用"校验+定向重试"根治）；两个真实短板（水源漏检、画质低报）已定位并给出兜底建议。**

## 4. 汇总统计

### 4.1 通过率（两种口径）

| 口径 | 数值 | 说明 |
|---|---|---|
| 严格口径（结构+枚举+禁止项+内容全过） | 档位 9/20 = 45% | 含格式失败 |
| **内容口径（只看内容判断对错）** | **77/85 项 = 90.6%** | 8 项内容失手：水质 4、画质 3、趋势 1 |
| 格式-only 失败（内容全对） | 6 档位（001C/002C/003B/003C/007B/010A） | 围栏 3 + 枚举 3；**服务端校验可根治** |
| 红线禁止项扫描 | **48 次调用 0 违规** | FLP/面积/风速/无人机调度/absent/取水判断等 9 类红线词全部零出现 |
| 身份回显（task_id/轮次/图片编号照抄） | 0 错误 | |
| 防幻觉关键项 | 全部通过 | 只见烟→smoke_only；无火+假YOLO框→仍判无火且上报矛盾；替代递减组→未编造明火 |

### 4.2 耗时（38 份落盘证据）

| 指标 | 值 |
|---|---|
| 纯模型耗时（无重试的 13 次调用） | 中位 **19 秒**，最快 10 秒，最慢 51 秒 |
| 含限流等待的总耗时 | 中位 44 秒，最慢 332 秒（含约 5 分钟退避） |
| 思考型输出 | completion 中 69% 为 reasoning tokens（该模型输出前先推理，属正常） |

### 4.3 令牌消耗（37 次成功调用）

prompt 合计 91,950 + completion 合计 49,320 ≈ **14.1 万 tokens**（免费模型，成本 ¥0）。单次典型：prompt 1.4K–5.1K（多图最大），completion 0.5K–2.0K。

### 4.4 限流（晚高峰为主要工程风险）

- 全程 48 次调用中 **11 次失败于限流/空响应**（全部发生在 19:00–22:00 高峰；其中 CASE-001C 连续 2 次、CASE-010A-v4 连续 2 次未获有效输出）
- 59 次重试事件分布在 25/38 次调用上；退避阶梯 [15,40,90,150] 秒基本够用，极高峰仍会耗尽
- 另发现 **1 次 HTTP 200 但返回内容为空**（新失败模式，见 P07）

## 5. 内容能力结论

**强项（可放心依赖）：**
1. 明火/烟识别与分级：全部正确（含夜间微弱火光带、远处火线）
2. 防幻觉：只见烟不报火、无火不被假YOLO框带偏、且能主动上报"YOLO与画面矛盾"
3. 人员识别：近距离多人（7–8名）正确 observed+证据
4. 建筑识别：远处红屋顶一角正确 observed+证据
5. 帧间递增判断（真实同场景视频两帧）：正确 intensifying
6. 红线纪律：FLP/面积/风速/调度等 9 类禁止项 0 违规；身份字段照抄 0 错误

**短板（需兜底，不可单独依赖）：**
1. **水源漏检（0/2）**：画面下半部明显湍急河流，两档均报 not_observed、证据为空
2. **画质自我评估乐观（0/2）**：夜间近黑图与偏模糊+遮挡图均评 problems=['none']
3. 多图趋势判断在"非真实连续帧"场景仍会退回 first_round_no_comparison（v4 规则修复了真实对比组，替代组合仍失败）

## 7. 给开发者的接入建议（按优先级）

1. **结构校验 + 定向修复重试**：收到响应先剥离围栏→JSON解析→按 vlm-analysis-v1 校验枚举；失败时把**具体错误字段**回传模型重试一次（本测试的"格式修复重试"机制已验证可行，CASE-010 曾靠它救回一次）。此机制可同时根治 P01/P02。
2. **限流对策**：调用间隔≥6秒、指数退避重试（本测试参数：[15,40,90,150]秒）；尽量避免晚高峰批量调用；HTTP 200 空响应按失败重试（P07）。
3. **水源/画质不要单信 VLM**：water 与 image_quality 字段仅作参考，用水源决策走 PWM-YOLO/人工，图片可用性由采集端控制。
4. **多图轮次**：按 v4 提示词 + 帧序列说明行（见 prompt-v4.md §三）；temporal_trend 仅在多图或存在上一轮时有效。
5. **温度与上限**：temperature 0.1、max_tokens 2048 维持（本测试全部在此参数下完成）。
