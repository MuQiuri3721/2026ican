# 压制能力与火情边界分析(为什么有的火压不住)

> 2026-09-08 · BE-13 第四批再生版：全部边界数字由**统一分钟推进核心**（`backend/app/rules/simulation.py`
> 的 `advance_one_minute`，预测与执行同一套规则）二分扫描实测得出，可用
> `tests/test_simulation_consistency.py` 与附录复现命令逐值复现。旧版手填数值
> （系数 90 与 108 混用、857/1029/731 同格三值）已废弃。
> 依据：configs/simulation.json `v1` 冻结段 + docs/无人机子群与参数规则1.md。
> 结论先行：**压制是"占空比打折的常数"，火势增长是"比率复利"——FLP 越过边界后
> 每轮缺口复利放大，系统如实输出"不可控 + 资源缺口"，而不是无限推演或调参造成功。**

## 结论分类口径（评审 §问题7 要求的三分法）

| 结论 | 判定条件 | 含义 |
|---|---|---|
| **时限未完成** | 稳态压制 N×P ≥ 增长 FLP×g/12，但 120 min 仿真限内未归零 | 方案方向正确，"慢压"：继续推演最终可灭（如 370 FLP/2 架案例） |
| **资源不足** | 稳态压制 < 增长（FLP > N×P×12/g） | 必须增援/调上限，推演多久都压不住（如 810 FLP/4 架案例） |
| **计算或状态异常** | 出现 stalled/异常事件、相同输入复现不出相同结果 | 程序缺陷，走缺陷流程，**不得**归因于资源 |

P = 单机每轮有效压制（理想占空比 7.5，实测 6.5~7.5 FLP/轮，随距离/风档/SOC 浮动）。

## 二、单机压制模型:占空比决定一切

一架灭火机的完整循环(以基地距火点 ~660 m、速度 8 m/s 为例):

```text
出动 1.4 min → 喷洒 5 min(20L÷4L/min)→ 返航 1.4 min → 补水 4 min
循环 ≈ 11.8 min ≈ 2.4 轮;在火场喷洒占比 = 5/11.8 ≈ 42%
```

- 单架次压制 = 20L × κ1.0 × η0.9 = **18 FLP**
- 单机每轮压制 ≈ 18 ÷ 2.4 ≈ **7.5 FLP/轮**(风档升高 η 降到 0.85/0.65 时更低;
  距离更远、SOC 触发返航换电时占空比再降——实测校准 **6.5~7.5 FLP/轮/架**)

**关键认知:灭火机的火力不是"持续输出",是"占空比打折扣后的平均值"。**
基地不在火边、水要来回背、电要换——这些真实的后勤约束就是压制的天花板。

## 三、火势增长模型:比率复利(分母恒定,审批无关)

冻结语义(BE-13 后):`growth_rate_per_hour` 是场景/观测层的**比例增长率**,随方案
生成后只随"新观测重规划"更新;approve/adjust 只盖 `replan_trigger_baseline_flp`
触发线,**不得改变增长速度**。

```text
每分钟: FLP ← FLP × (1 + g/60) − 本分钟压制     （g = growth_rate_per_hour）
每 5 分钟轮近似: FLP × (1 + g/12) − 本轮压制
```

**增长与 FLP 成正比(复利):火越大,每轮净增越多;压制受占空比限制,越过边界后追不上发散段。**

## 四、能力边界:两个口径必须分开

### 4.1 稳态平衡点(无限时视野,理论)

`N × P ≥ FLP × g ÷ 12` ⇔ **稳态可控 FLP ≈ N × P × 12 ÷ g**(P≈7.5 理想 / 6.5 实测折扣)

### 4.2 120 分钟限内实测可控上限(统一核心二分扫描,交付口径)

条件:植被火 / 风 3 m/s(η=0.9) / 默认库存 / 水剂可参战机 E1-E6+S3/S4 池 / 24 轮×5 min 仿真限。
**以下每个格子都由与正式执行同一套 `advance_one_minute` 规则实算,不是公式外推:**

| 出动灭火机数 N | g=0.1 | g=0.2 | g=0.3 | g=0.42 |
|---|---|---|---|---|
| 1 架 | FLP ≤ 114 | ≤ 104 | ≤ 95 | ≤ 86 |
| 2 架 | ≤ 229 | ≤ 209 | ≤ 191 | ≤ 172 |
| 3 架 | ≤ 343 | ≤ 313 | ≤ 286 | ≤ 258 |
| 4 架(默认) | ≤ 458 | ≤ 417 | ≤ 382 | ≤ 345 |
| 5 架 | ≤ 569 | ≤ 518 | ≤ 474 | ≤ 428 |
| 6 架 | ≤ 667 | ≤ 609 | ≤ 558 | ≤ 504 |
| 7 架 | ≤ 743 | ≤ 680 | ≤ 625 | ≤ 568 |

复现:`python - <<'EOF'` 二分 `simulate_dispatch_candidate`(N=pool[:n],growth_rate_per_hour=g),
或直接跑 `pytest tests/test_simulation_consistency.py -q`。

**稳态口径 ≠ 时限口径**:4 架/0.42 的稳态平衡点 ≈ 857 FLP,但 120 min 内实际可控只有
**345 FLP**——从高处压到零需要净衰减多轮,有限视野吃不到稳态。旧版把 857(甚至按
系数 108 算成 1029)直接当"可控上限"写进表格,正是"预测说可控、执行压不住"的根源之一。

## 五、实测验证与历史现象对账

2026-09-07~08 的旧实测(离线确定性,风 3.05 m/s)产生于**旧两套仿真口径**,按评审§二
只作现象记录,不作为 2+6+4 版本的验证;其结论与统一核心边界表对账如下:

| 火情 | FLP 起步 | 出动 | 旧实测现象 | 统一核心对账(4.2 表) |
|---|---|---|---|---|
| 400 m² / 0.3 | 60 | 4 架 | ✅ 扑灭(60→27→0) | 60 ≪ 382 → 速灭 ✓ |
| 1800 m² / 0.42 | 810 | 4 架 | 🔴 30 轮 810→1356 | 810 > 345 且 > 稳态 857 边缘 → 资源不足 ✓ |
| 3000 m² / 0.5 | 1847 | 4 架含 S3/S4 | 🔴 5 轮 +47~84/轮 | 1847 ≫ 382(g=0.3 折算) → 资源不足 ✓ |
| 6000 m² / 0.9 | 3600 | 4 架 | 🔴 3 轮触发 +20% 重规划 | 远超 → 不可控 ✓ |
| 1800 m² 实况风(FLP 370) | 370 | 2 架 | 🟡 21 轮受控,70 轮降至 116 仍在降 | 370 > 172(时限内不可控)但 < 稳态 429 → **时限未完成型慢压** ✓ |

**资源不足**与**慢压**两类——这正是旧文档做不到的。

## 六、为什么压不住:设计溯源(每条都是有意为之,附代价)

1. **5 分钟轮次 + 真实后勤循环**(规则文档 §7):弹药有限、要返航补水、要换电——
   真实无人机没有无限弹药。代价:占空比 ~40%,压制天花板由此而来。
2. **增长按比率复利**:冻结公式 `FLP × g` 保证火越大涨越快;审批/重规划不得改变 g
   (BE-13 问题4)。代价:越过边界后缺口指数放大,不会自己好。
3. **出动上限(动态,默认 4,上限=可参战灭火机 8=E1-E6+多用途 S3/S4)**:BE-13 第三批
   解除写死的 4 架钳位,前后端同口径,禁用名单动态生成。代价:上限即瞬时火力上限,
   大火需要用户主动调高上限并配合增援。
4. **J 评分 24 轮仿真视野**(§4.2 的 120 min):调度器只推荐限内可控的组合。
   代价:稳态可控但需要 25+ 轮的"慢压"方案会被判不可控——按三分法归入
   "时限未完成",系统如实给出缺口而不是假装可控。
5. **诚实的不可控边界**:FLP 超限时输出 `effective_flp` 缺口 + "请求增援",
   不产虚假时间窗、不假装可控(规则文档 §8.2 / api-contract §7)。代价:演示里会
   出现"压不住"的场景——这是能力边界的如实呈现,不是缺陷。
6. **历史缺陷回溯**(均已修复,见修改追踪清单):
   - FE-32:换电机制缺失 → E 机喷一轮就趴窝充电 45 分钟,压制 ≈ 0,"火越灭越大"的
     第一次真凶;
   - BE-12:余烬级(<20 FLP)±1 FLP 波动触发相对阈值 → 清扫阶段重规划风暴;
   - FE-39:重规划未续接火势/风速 → 每轮从初值重飞的死循环;
   - BE-13:增长分母被审批改写、药剂按方案统一混算、跨轮进度归零、预测执行两套仿真、
     出动上限硬编码 4(本文档§一~§五即为修复后的统一口径)。

## 八、若要提高压制能力上限(需走规则变更流程,双人在场确认)

按 §4.1/§4.2,可选杠杆:
1. 提高出动架数(默认 4→8 已接通 2+6+4;再往上需扩编机群,当前阶段冻结);
2. 前向补给点缩短补给循环(已有 `forward_supply_points` 机制,提高占空比 P);
3. 提高单机载荷(更大水罐模块 → 改 `v1.spray` 参数,**冻结项,需双人确认**);
4. 降低 growth_rate(火情参数由场景给定,不属于系统能力,**禁止**用降火势参数制造成功)。
