# 需求与设计思路

> 本文由原 `requirements.md`（需求摘要）与 `思路细化.md`（设计思路细化）两份同类文档合并而成（BE-14 文档整理，2026-09-08），并同步当前口径：2+6+4 十二架机群、持久化/在线气象/OSM GIS 已实现、VLM 职责三类收窄、紫霞湖真实 GPS 锚定。知识库检索副本独立存放于 `data/knowledge/思路细化.md`，不受本次合并影响。

## 一、项目目标

系统面向森林火灾应急指挥演示，围绕紫金山（紫霞湖基地锚点）固定森林区域，完成"感知—研判—调度—审批—执行模拟—反馈重规划—报告归档"的可视化闭环。输入包括地点或坐标、图片/图片序列/MP4、环境快照、2+6+4 虚拟机群状态和物资库存；输出包括火情类型与 FLP、风险解释、资源需求、候选调度、审批状态、轮次变化和归档报告。

数字由规则引擎和调度算法计算，智能体负责调用工具、组织顺序、处理分支并解释结论——大模型不直接猜关键数值。

## 二、资源与规则边界

- 资源池为 2 架侦察 R1–R2、6 架灭火 E1–E6、4 架支援 S1–S4（S3/S4 为 multi_role 多用途支援机，可参战灭火，计入出动上限 8）；子群是角色层级，每架 UAV 独立记录，按需出动（1..上限逐数量枚举，不默认全员）。
- 火情负荷以 FLP 表示，地图按 100 m² 网格呈现，不把固定面积/升水能力作为核心规则。
- W20 水剂用于一般植被火；C6 CO₂ 用于电气/油类/化学品火与局部热点，每架按自身装载模块计量（W20 计升、C6 计千克），同一架次不混装。
- SOC 以 `%/h` 参数录入、按 1 分钟内部更新；每 5 分钟形成反馈轮次；返航 SOC ≥25%、复飞需 ≥25% 且机上有机剂。
- 先满足药剂兼容、载荷、SOC、路线、健康度和人员保护等硬约束，再进行时间、风险、耗电和物资评分。
- 时间输出为仿真区间、三态裁决（can_control/maintain_only/cannot_control）或资源缺口，不硬编码"18 分钟"单点结论。

## 三、自动获取与用户输入

| 信息 | 来源/交互方式 |
|---|---|
| 火灾地点、坐标 | 用户输入或预警系统传入（紫霞湖 GPS 锚定） |
| 连续火情图像 | 演示上传图片序列/MP4（自动抽帧）；真实无人机回传待接 |
| 火点、火焰、烟雾 | PWM-YOLO 自动识别（真实权重待交付 E-1，fixture/mock 就绪） |
| 火势变化方向 | 连续图像趋势 + 环境数据综合判断 |
| 风速、风向 | Open-Meteo 在线气象（离线回退标注来源） |
| 地形、海拔、坡度、等高线 | 真实 DEM（N32E118.hgt）+ 等高线服务 |
| 森林边界、道路、水源 | OSM Overpass 自动查询（离线回退场景 JSON） |
| 无人机位置、电量、载荷 | 虚拟机群状态数据库自动读取 |
| 物资库存 | 系统库存数据库读取（只读；用户更新入口属演示裁剪） |
| 是否存在人员 | VLM/YOLO 识别 + 用户确认 |
| 目标处置时限 | 用户可选输入 |
| 是否执行方案 | 用户最终确认 |

用户交互只发生在：发起任务、补充系统无法自动获得的信息（人员/时限/禁用设备）、确认或拒绝/调整/终止方案。

## 四、模块职责

### 4.1 视觉感知（PWM-YOLO + VLM）

- YOLO：火点位置、火焰/烟雾检测、覆盖比例、前后帧趋势、置信度；视觉结果不生成风速、真实面积或 SOC。
- VLM（glm-4.6v-flash）：理解火场图像、结合 YOLO 结果解释火情、判断人员/水源/火势现象、输出结构化 `vlm-analysis-v1` 描述并发现冲突。VLM 职责收窄为三类（人员/水源/现象），道路建筑障碍解释由规则回退解释器承担；VLM 不直接决定数量、能耗、效果。

### 4.2 环境与资源

环境：地形地貌、海拔坡度、森林边界、水源可用状态、道路疏散出口、风速风向（在线优先、离线标注来源）。资源：读取每架无人机位置、电量、速度、载荷、模块、状态与可执行任务；支援子群"充电"实现为备用电池换电（5 min→95%）与补给点补能语义，不描述空中直接给另一架充电。

## 五、智能体决策边界

| 决策 | 实现方式 |
|---|---|
| 风险等级 / 出动数量 | 风险评分规则 / 约束筛选 + 逐数量枚举评分 |
| 使用物资 / 是否就地取水 | 火型 + 库存规则 / 六条件真实评估（可用、安全、容量≥20L、路线安全、循环 SOC≥25%、节省≥5min） |
| 每架任务 | 约束筛选 + 编组分工（R 主监测/复核、E 压制 + 通道保护、S1/S2 按人员分支分工） |
| 疏散路线 | 火点/烟雾/道路/出口路径（confirmed 分支自动产出 EvacuationSkill） |
| 是否完成 / 预计时间 | 统一分钟核心仿真 vs 增长趋势 / 三态裁决 + 时间区间 |
| 无法完成的原因 | 物资、电量、数量、距离或火势约束 → resource_gap |

规则引擎负责计算；智能体负责调用工具、组织顺序、处理有人/无人和异常分支、解释数字来源。作业高度档位属演示裁剪（无飞控/气动模型，纯标签）。

## 六、人员分支与反馈闭环

确认有人：识别人员位置 → 风险区设定 → 读取道路出口 → 规划避险路线 → 支援子群广播/照明/指引 → 保留 1 架 E 保护疏散通道，路线随方案/地图呈现。确认无人：S1 物流补给/电池前送、S2 通信中继与后备侦察。不确定：S1 复核人员、S2 中继待命；不把全部可战灭火机投入远端。

闭环采用 5 分钟对外轮次（内部 1 分钟推进），系统重新判断原方案有效性、追加物资、更换无人机、增援、疏散分支或结束任务。重规划触发器：FLP 相对审批触发基线 +20%（≥20 FLP 下限）、风档跨变、返航 SOC 告警、药剂断供、人员变化、信号低于阈值、GLM 自主研判（趋势闸门内）。扑灭后结案回收，全员返航归档。

## 七、范围（2026-09-30 前）

必须完成：地点输入、图片/视频上传与抽帧、检测结果展示、固定场景环境查询、虚拟机群与库存状态、VLM 火情解释、风险研判、数量与任务分配、有人/无人/不确定分支、方案审批闭环、反馈与重规划、最终报告归档——**全部已实现**。

有意排除（暂不实现）：真实飞控、连续实时视频流、全国 GIS 全量、复杂三维火场仿真、多用户认证。历史排除项中"持久化数据库 / 在线气象 / GIS 查询"已分别以 SQLite 写穿、Open-Meteo、OSM Overpass 实现，不再列为排除。

交互原则：首屏只要求地点或坐标；连续图像带时间顺序与来源；信息不足才追问；方案必须"待确认"；所有数字带单位/来源/更新时间；不用聊天文本替代结构化表单；不可行方案必须说明触发的硬约束与资源缺口。方案卡片展示风险等级、FLP、选中 UAV 与任务、药剂、时间区间/三态裁决、人员分支、硬约束、备选、缺口与重规划触发条件。
