# 答辩速查卡（评委问答 · 人手一份）

> 每条答法控制在两句话内。口径红线见底部；详细依据见括号内文档。

## 一、术语表（30 秒讲清）

| 术语 | 一句话定义 |
|---|---|
| **FLP** | 标准化火情处置负荷：综合过火面积、燃料、坡度、风速按冻结公式折算的任务难度值（界面同时给 m² 直读） |
| **SOC** | 无人机电量百分比；预计返航 SOC ≥ 25% 是硬约束，低于即自动返航 |
| **W20 / C6** | 两种药剂：W20 水剂（一般植被火，20L 模块）/ C6 干粉（电气/设备火，6kg 模块），同架次不混装 |
| **审批门** | 生成方案 ≠ 执行；必须指挥员确认后才锁定资源出动。驳回/终止/重规划全部留痕 |
| **三态结论** | 可完全控制 / 可维持压制 / 不可控（诚实请求增援），与原因码同源输出 |
| **时间区间** | 扑灭时间窗输出为区间（如 10–14 分钟），不是单点拍脑袋；不可能达成时输出"—"+缺口原因 |

## 二、必问问题与答法

**Q1 FLP 公式和 K 值的科学依据？**
参数来自需求输入规则文档，全部显式配置（configs/simulation.json）可审计；压制能力边界有专门标定文档（docs/压制能力与火情边界分析.md，实测四例吻合）；所有数字来源在界面逐项标注，绝不现场编造。

**Q2 调度为什么不用强化学习/优化求解器？**
安全关键决策要求可解释、可复现、可审计——确定性评分 + 硬约束过滤 + 组合枚举在 12 机规模下是最优区间内的可证解；调度器接口化，可替换 OR-Tools/RL 而不动链路。

**Q3 多智能体的"协作"体现在哪？**
分层决策架构：规则引擎算所有安全关键数字；六角色 Agent（指挥/侦察/压制/支援/研判/审批）通过黑板消息组织任务、产出发现与建议（全程可回放）；GLM 参与研判与 replan 建议但带趋势闸门，且永远绕不过人工审批。

**Q4 LLM/VLM 幻觉怎么防？**
三层：VLM 输出过 JSON 契约守卫（身份回显校验、禁项剥除、语义钳位）；FLP/面积/调度数字只出自规则引擎（模型被提示词禁止输出数字）；指挥员问答带数字审计，编造数字标 ⚠。

**Q5 换一个山区还能用吗？**
能。real 模式支持任意经纬度：DEM 高程、Open-Meteo 气象、OSM 水源/路网全部动态拉取；紫金山是演示冻结场景。数据失效时如实标注 offline/demo-fallback，不虚构。

**Q6 检测和执行是真实的吗？**
如实边界：YOLO 当前为 fixture（界面标注"对接就绪"——检测接收面协议已备好，真实权重到位即插即用）；任务执行为仿真状态机（README 明示），接口面为真实飞控适配器预留。视觉理解 VLM 是真实云端模型（glm-4.6v-flash）。

**Q7 预测和执行会不一致吗？**
共用同一个"分钟推进核心"（advance_one_minute），预测与闭环执行走同一状态机，一致性有专门回归测试锁定。

**Q8 图像数据出云合规吗？**
视觉模型经适配器架构接入，生产可切换本地化部署模型；当前演示使用云端免费档，界面来源徽标如实标注。

**Q9 系统的容量/并发？**
演示规模设计：单实例 SQLite 写穿持久化，任务级资源锁互斥（冲突 409 并列出占用者），僵尸任务 30 分钟自动回收。

**Q10 怎么保证演示不是"演的"？**
全部自动化测试可复现：189 项 pytest、20 轮浏览器 E2E（139+ 断言）、44 项 API 边界扫描、六场景验收；冻结场景 data/frozen_scenarios/ 固定输入可复跑。

## 三、口径红线（说错扣分）

1. VLM（glm-4.6v-flash）**已真实接入**——别说"未来接入"。
2. YOLO：已训练自有模型 **yolo11n-dfire-v1**（D-Fire 5,134 图，mAP50 0.719 / 官方 test 集 0.665，单帧推理 1.4ms）并接入实时服务；PWM-Net 原始权重到位后同端点切换。**不宣称达到生产级精度**。
3. 所有调度数字出自冻结规则公式；LLM/VLM 只建议、描述与叙述，带来源标注。
4. 开火（出动）与重规划**必过人工审批**——AI 永远绕不过人。
5. 降级是设计行为不是故障：看到"离线规则"徽标就讲"规则引擎是底线，演示永不中断"。

| 状况 | 表现 | 处置 |
